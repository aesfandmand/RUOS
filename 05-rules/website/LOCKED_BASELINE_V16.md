## Binding rule

This approved V16 is the visual, interaction, motion, mobile and content-quality floor for all subsequent pages. New pages are upgrades on this baseline, not redesigns from zero.

A delivery is rejected when it is weaker than V16 in any of these areas:

- information architecture and section completeness;
- header, navigation, logo, tagline and footer integrity;
- Persian typography and embedded-font reliability;
- mobile and iPhone behavior;
- interaction, scroll narrative and motion quality;
- visual depth, imagery and composition;
- content usefulness, specificity and brand voice;
- accessibility, touch targets and readable contrast.

## Non-regression protocol

Before implementation, every page task must declare:

1. baseline file and checksum;
2. approved reference sources;
3. allowed and forbidden changes;
4. page intent, persona, pillar and cluster;
5. capability and evidence used;
6. measurable non-regression checks.

After implementation, the delivery must include a baseline diff and a non-regression report. A failed gate means the output is not a delivery.

## Versioning

- V16 remains immutable.
- All experiments start from a new version or branch.
- V16 can only be replaced by explicit written owner approval.

## Explicit visual prohibition

The recurring black-to-red / red-to-black hero-gradient treatment is not a default brand pattern and must not be used unless the owner explicitly approves it for a specific page.
