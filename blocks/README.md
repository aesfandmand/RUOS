# Block Library — V16 baseline

هر بلوک یک الگوی ترکیب‌بندی مستقل و **خودکفا** است: قرارداد، قالب، CSS و
دارایی‌هایش در یک پوشه‌اند. سقف کیفیت هر صفحه‌ای که موتور می‌سازد برابر است با
کیفیت همین کتابخانه، نه با هوشمندی مرحلهٔ تولید.

## منشأ

بلوک‌ها از `services-urban-investment-final-v16.html` استخراج شده‌اند — همان
نسخه‌ای که مالک تأیید کرده و `05-rules/website/LOCKED_BASELINE_V16.md` آن را کف
کیفیت اعلام می‌کند. تقسیم CSS بدون از دست رفتن حتی یک اعلان انجام شد (۱۳۰۲ اعلان).

## ساختار

```
blocks/<id>/
├── block.json     قرارداد: خانواده، سطح، نیت، اسلات‌ها، قواعد مجاورت
├── markup.html    قالب؛ اسلات‌های آن با block.json هم‌گام است
├── style.css      CSS محدود به همین بلوک
├── behavior.js    اختیاری
└── assets/        تصاویر مخصوص بلوک
```

قرارداد و دارایی JSON و فایل‌اند، نه YAML، تا موتور بدون وابستگی نصب شود.

## زبان قالب

`{{name}}` متن escape‌شده · `{{{name}}}` markup خام (فقط برای دارایی خود پروژه) ·
`{{#list}}…{{/}}` تکرار · `{{?name}}…{{/}}` شرط · `{{@nn}}` شمارهٔ دو رقمی.

## قواعدی که کامپوزیتور رد می‌کند (نه هشدار)

هر بلوک دو صفت جدا دارد: `family` می‌گوید **چه معنایی** دارد و `layout` می‌گوید
**چه شکلی** است. جداکردن این دو لازم بود، چون پنج بخش با معناهای متفاوت
(evidence / statement / knowledge) همگی به یک شبکهٔ کارت یکسان می‌رسیدند و قانون
مبتنی بر معنا آن‌ها را پاس می‌کرد.

- دو بلوک هم‌خانواده کنار هم
- **دو بلوک هم‌شکل کنار هم** (`layout` یکسان)
- **حداکثر دو بخش `card-grid` در کل صفحه** — شبکهٔ کارت شکل پیش‌فرض است و
  استدلالی از خودش ندارد؛ صفحه‌ای که بیشترش کارت باشد فهرست است، نه صفحه
- بیش از دو سطح هم‌رنگ پشت سر هم
- صفحه باید با `first` باز و با `last` بسته شود
- اسلات اجباری غایب، فهرست خارج از بازه، اسلات ناشناخته
- فقط CSS، JS و دارایی بلوک‌های استفاده‌شده وارد خروجی می‌شود

## تفاوت‌های عمدی با V16

| مورد | V16 | اینجا |
|---|---|---|
| فونت | جاسازی‌شده در HTML | در `_tokens` — یک بار، قابل کش |
| تصاویر | base64 داخل HTML (۴ مگابایت) | فایل واقعی در `assets/` (HTML: ۶۲ کیلوبایت) |
| منوی موبایل | فقط CSS؛ دکمه کاری نمی‌کرد | markup اضافه شد و کار می‌کند |
| اعداد تزئینی | خوانده می‌شدند | `aria-hidden` |

## صفحهٔ مرجع V16 خودش این قواعد را رد می‌کند

دنبالهٔ V16 پنج بخش `card-grid` دارد و دو بخش `sticky-track` را هم پشت سر هم
می‌گذارد:

| بخش | شکل |
|---|---|
| contract-section | card-grid |
| proof-section-final | card-grid |
| media-section-final | card-grid |
| audience-section-final | card-grid |
| knowledge-section-final | card-grid |

این عمدی ثبت شده و تستی هم دارد. یعنی V16 کف کیفیت **بصری** است، ولی
ترکیب‌بندی دنباله‌اش هنوز کار باز است: این پنج بخش به شکل‌های جایگزین نیاز دارند
که باید از مراجع تأییدشدهٔ مالک بیاید، نه از طراحی فی‌البداهه.

## بدهی شناخته‌شده

۴۱ افت کنتراست از V16 به ارث رسیده (بدترین ۱.۸۷:۱)، عمدتاً متن‌های کم‌رنگ روی
سطح کاغذی. این رگرسیون نیست — در خود V16 هم هست — ولی باید در لایهٔ توکن رفع شود.

کوریوگرافی اسکرول V16 یک حلقهٔ واحد است که هیرو، فرصت‌ها و مسیرها را با هم
می‌خواند؛ بنابراین سطح-صفحه است و در `_foundation` می‌ماند، نه در تک‌تک بلوک‌ها.
